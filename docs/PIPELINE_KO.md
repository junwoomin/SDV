## 센서 수집과 저장

수집기는 같은 CARLA 프레임의 센서 패킷을 맞춰 장면에 저장합니다. 파일 이름의 표본 인덱스와 CARLA native Frame ID는 별도로 기록합니다. 수집 당시 `sensor_config.yaml`과 `collection_manifest.json`이 좌표·단위·보정의 기준입니다.

| 자료 | 저장·처리 의미 |
| --- | --- |
| RGB | 카메라 입력 이미지 |
| Segmentation | 원본 CARLA ID와 팔레트 미리보기; 학습에서는 선택한 ID를 Head 인덱스로 매핑 |
| Depth | 새 수집의 float32 미터 NPY와 PNG 미리보기; 기존 자료는 manifest의 인코딩에 따라 해석 |
| Object Detection | 카메라 픽셀 좌표의 `N×5 [x1,y1,x2,y2,class_id]` 주석; 빈 주석과 누락 파일을 구분 |
| BEV | 정적·동적 레이어, 높이와 유효성 정보; 실제 제공 채널만 사용 |
| LiDAR·IMU·ego 정보 | 원본 프레임·시간 및 좌표 계약을 manifest와 메타데이터에서 확인 |

기존 LiDAR 저장 계약은 네 열 전체에 2배 배율을 적용합니다. native CARLA 값으로 사용할 때는 manifest에 기록된 배율을 복원해야 합니다. 이전 자료에 없는 시간·신호 상태·도로 정보는 N/A로 유지합니다.

## 데이터셋과 품질 검사

서로 다른 완전한 장면을 TRAIN·VAL로 배정하고 보정과 함께 복사합니다. 같은 장면의 인접 프레임을 두 분할에 섞으면 평가 누출이 생길 수 있습니다. 준비 검사에서는 파일 정렬, 센서 보정, 태스크별 입력·정답과 BEV 스키마 호환성을 확인합니다.

시퀀스 분석 화면은 선택 Frame의 RGB·Seg·Depth·OD·BEV를 함께 재생합니다. 품질 검사는 프레임 누락, 라벨 범위, 박스 형식, 깊이 유효성, 시간·ego 상태 등을 확인합니다. 이전 자료의 파일 이름 일치만으로 native 센서 동기화를 입증할 수는 없습니다.

## 학습과 결과

선택한 태스크마다 클래스, 손실, 유효성 마스크와 지표를 연결합니다. 고정 VAL 표본과 저장된 TRAIN 표본의 입력·정답·예측을 Epoch/Iteration별로 탐색합니다. 실험 비교에는 일치하는 데이터셋 fingerprint가 필요합니다.

일시정지·재개는 Epoch 경계와 호환 체크포인트를 사용합니다. 모델, 데이터 처리 계약 또는 설정이 맞지 않는 체크포인트는 재개 검사에서 차단합니다. 데이터 처리 계약이 달라진 이전 실험은 해당 코드로 재개하거나 새 실험으로 시작해야 합니다.

## Planning 내보내기와 연구 범위

Planning 내보내기는 현재 관측과 이후 기록에서 계산한 미래 위치·제어를 분리합니다. 세션 경계·시간 역전·누락·Teleport를 넘어 연결하지 않습니다. 온라인 계획 waypoint와 실제 미래 궤적은 별도 자료입니다. native timestamp가 없는 자료는 표본 간격만 제공하며 실제 초 단위 간격을 추정해 채우지 않습니다.

BEV 학습의 카메라 optical/CARLA 축 변환은 추가 기하 검증 대상입니다. 기존 수집 범위, 학습 crop과 projection grid는 서로 구분해야 합니다. Planning 내보내기의 실제 TCP 입력·Target 호환성도 별도 어댑터와 평가가 필요합니다.
