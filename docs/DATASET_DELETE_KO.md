# 주행 시퀀스 데이터셋 삭제

시뮬레이션 → 시퀀스 분석·데이터셋의 **수집된 Scene 표**에서 해당 행의 **삭제**를 누른다. 미리보기 선택 없이 바로 삭제할 수 있다. 확인 창에서 Scene 이름·경로·샘플 수를 확인하고 **확인** 또는 **취소**를 선택한다. 이름 입력은 요구하지 않는다.

주행 시퀀스 분석 또는 저장 데이터 재생의 **데이터셋 삭제** 버튼도 같은 확인·취소 방식을 사용한다.

선택한 수집 Scene의 이미지·라벨·Metadata 파일을 실제로 영구 삭제한다. 복구 기능은 없으며 취소하면 삭제하지 않는다. 학습·검증용으로 이미 복사한 다른 Scene이나 실험 결과는 삭제하지 않는다. 성공 후 데이터셋 목록, Timeline 및 이미지 캐시를 갱신한다.

실행·일시정지 중이거나 대기열에 있는 작업의 저장된 데이터 경로가 해당 Scene과 겹치면 삭제를 차단한다. 현재 설정을 바꾸어도 기존 작업의 경로 보호는 유지된다. 그 작업을 완료하거나 대기열에서 제거한 뒤 삭제한다. 다른 데이터를 사용하는 작업은 삭제를 막지 않는다.

삭제 대상은 프로젝트 내부의 개별 원본 수집 Scene이다. 저장 루트·상위 폴더·프로젝트 외부·심볼릭 링크 경로 및 Train/Val 복사본을 이 화면에서 삭제하지 않는다. 내부 링크가 가리키는 외부 파일도 삭제하지 않는다. 파일 권한 오류는 원인과 부분 삭제 가능성을 안내한다.

API는 `GET /api/datasets/{id}/deletion`으로 삭제 가능 여부와 실제 Scene 이름을 조회하고, 사용자가 확인한 후 UI가 `DELETE /api/datasets/{id}`에 그 이름을 `confirmation_name`으로 전달한다. 기존 인증·동일 출처·변경 요청 헤더 검사를 적용하며 작업 시작·데이터 준비와 같은 자원 잠금을 사용한다.

삭제 API 구현 파일은 `studio/dataset_delete.py`, `api.py`, `sequences.py`와 관련 테스트다. 이번 표·확인 창 변경은 `static/app.js`, `pipeline-ui.js` 및 문서에 적용했다. 최초 삭제 기능의 v10 대비 파일 목록은 `DATASET_DELETE_CHANGED_FILES.json`, 이번 UI의 v11 대비 목록은 `DATASET_DELETE_ROW_CHANGED_FILES.json`에 있다.

기존 삭제 API·작업 보호·외부 경로/링크·권한 실패·캐시·Sequence 회귀 검사 66개는 Python 3.7과 Python 3.12에서 각각 통과한 기록이다. 이번 변경은 프론트엔드에 한정했다. 새 Chromium 검증에서는 표의 삭제 → 취소 시 파일 보존, 이름 입력 없이 확인 → 해당 Scene만 삭제, 목록 갱신, 분석 영역의 동일 확인 창, KO/EN 문구와 두 화면 크기를 확인했다. 임시 데이터셋만 사용했으며 사용자 데이터는 삭제하지 않았다. 이번 UI 결과는 `dataset-delete-row-browser-validation.json`, 기존 API 결과는 `validation/dataset-delete-*-tests.xml`에 있다.
