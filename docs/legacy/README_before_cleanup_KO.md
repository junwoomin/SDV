## 시작

```bash
cd sdv_studio
chmod +x start.sh
./start.sh
```

`./start.sh`는 독립적으로 실행한 CARLA나 학습 프로세스를 종료하지 않습니다. 앱이 실행한 엔진만 소유권을 확인하여 중지합니다. 준비된 `.venv-web`을 우선 재사용하며, 다른 Python은 `SDV_WEB_PYTHON`으로 지정합니다. 설정에서 기존 CARLA 설치 경로를 지정하면 재다운로드 없이 사용합니다.

브라우저에서 **http://127.0.0.1:8765** 접속. 종료는 실행 터미널에서 `Ctrl+C`를 누릅니다. 웹 서버가 연구 작업과 센서 미리보기를 먼저 정리한 뒤 자신이 시작한 CARLA 엔진을 종료합니다. 이미 연결한 외부 CARLA 서버는 종료하지 않습니다.

- 웹 Python: **3.7 / 3.8 / 3.9 / 3.10 지원**. 3.10 이후 환경도 기존처럼 사용할 수 있습니다. `start.sh`가 활성화된 Python을 사용하고, 별도 `.venv-web`에 버전별 호환 의존성을 설치합니다. 기존 `aa` 환경의 CUDA/PyTorch/NumPy 패키지는 변경하지 않습니다.
- 기존 `.venv-web`의 Python 버전이 다르면 해당 폴더를 보존하고 `.venv-web-py37` 같은 별도 폴더를 사용합니다. 요구 의존성이 변경되면 다음 실행 때 자동 반영합니다.
- 프론트엔드: 별도 Node/npm 설치나 빌드 없이 제공됩니다. 한글 폰트도 포함되어 외부 CDN에 의존하지 않습니다.
- 연구 Python: 기존 CARLA·CUDA·PyTorch 환경을 **설정 → Python 실행 파일**에 지정합니다. 가상환경 Python 경로를 그대로 사용하세요.
- 다른 웹 Python을 사용하려면 `SDV_WEB_PYTHON=/path/to/python ./start.sh`.
- 최초 연구 Python을 지정하려면 `SDV_RESEARCH_PYTHON=/home/wo/anaconda3/envs/aa/bin/python ./start.sh`.
- 기존 프로젝트 `.venv/bin/python`이 있으면 최초 연구 환경으로 선택합니다. 이미 저장한 설정은 덮어쓰지 않습니다.

웹을 열기 위해 CUDA나 CARLA를 설치할 필요는 없습니다. 연구 작업을 시작하기 전에는 선택한 연구 Python에서 필요한 모듈과 CUDA 상태를 검사합니다. CUDA/PyTorch/torchvision/NumPy/torch-scatter는 자동으로 변경하지 않습니다. 시뮬레이션의 설치 후 실행은 선택한 연구 Python에 CARLA 클라이언트가 없을 때 `carla==0.9.15`만 설치한 뒤 엔진을 준비합니다. 일반 연구 의존성 목록은 `requirements/research.txt`에 있습니다.

## 처음 진행할 순서

수집 Scene을 지우려면 **시퀀스 분석 → 수집된 Scene 표 → 해당 행의 삭제 → 확인**을 사용합니다. 이름 입력 없이 확인·취소 창에서 결정하며, 확인하면 영구 삭제합니다. 해당 데이터를 사용하는 실행·대기·일시정지 작업은 먼저 완료하거나 제거해야 합니다. [삭제 기능 안내](../DATASET_DELETE_KO.md).

1. **설정**에서 프로젝트 이름, 연구 Python, CARLA 주소·포트, 저장 경로를 확인하고 저장합니다. 데이터·결과·로그 경로는 프로젝트 폴더 내부를 사용합니다.
2. **시뮬레이션** 최상단 CARLA 카드에서 **설치 후 실행**을 누릅니다. 선택한 연구 Python에 carla 패키지가 없으면 `carla==0.9.15`만 설치하고, 같은 Python에서 import·버전을 확인합니다. 이어서 엔진이 없으면 다운로드·설치하고, 실행 후 RPC가 준비되면 자동 연결합니다. **설치만**은 Python CARLA 패키지 없이 엔진만 내려받습니다. 이미 실행한 외부 서버는 기존 **연결 확인**을 사용하세요. **센서 설정**에서 숫자 입력이나 상단·측면 배치도 드래그로 위치를 조정하고, 실제 미리보기에서 확인한 뒤 설정을 저장합니다. 미리보기를 중지하고 타운·샘플 수를 정한 다음 준비 검사를 실행합니다.
3. **수집 시작**을 누릅니다. 선택 타운을 불러오므로 별도의 CARLA 세션을 사용하세요. 저장된 최신 프레임, 실제 저장 샘플 수, 주행 정보와 로그를 확인합니다. 중지해도 저장한 샘플은 남습니다.
4. 수집 결과를 **장면 단위로 분할**합니다. 같은 장면의 프레임을 학습과 검증에 섞지 않습니다. 학습에 선택한 카메라·출력 태스크에 필요한 모든 파일이 있어야 합니다.
5. **학습**에서 실제 데이터가 있는 입력 센서·출력 태스크와 모델·파라미터를 정합니다. 준비 상태 검사를 누르면 선택 인코더의 공식 사전학습 가중치를 백그라운드에서 준비하고, 자료·보정·CUDA·의존성을 함께 검사합니다. 다음 모델을 대기열에 추가하고, 필수 조건이 충족되면 자동 실행합니다.
6. **결과**에서 실행별 설정, 실제 학습 metric, checkpoint, 로그를 확인하고 비교·내보내기를 사용합니다.

## 학습 모니터링과 대기열

**학습 설정 → 학습 대기열 → 학습 모니터링**을 사용합니다. 실행 중에도 다음 모델의 설정과 데이터 경로를 저장하고 새 작업을 추가할 수 있습니다. 각 작업에는 추가 당시의 설정·센서 보정·데이터 경로 사본을 보관하며, 나중에 바꾼 기본 설정은 이미 실행 중이거나 대기 중인 모델을 바꾸지 않습니다.

- **대기열**: 실행 상태·진행·경과·예상 남은 시간, 대기 순서 변경, 일시정지·재개·삭제. 준비 조건을 충족하지 못한 첫 작업은 원인을 표시하며 기다립니다. 순서를 바꾸면 다른 준비된 작업을 먼저 실행할 수 있습니다.
- **일시정지**: 현재 Epoch의 Train·VAL을 마친 뒤 모델·옵티마이저·학습률 스케줄러·난수·누적 지표를 저장하고 종료합니다. 재개는 마지막 완료 Epoch의 **다음 Epoch**부터 이어집니다. 같은 실험의 설정·센서 보정·데이터 내용이 달라지면 재개를 거부합니다. 대기열 삭제는 저장된 실험 결과를 지우지 않습니다.
- **예측 기록**: 같은 내용의 VAL 데이터셋에는 모델과 무관하게 같은 최대 4개 샘플을 고정합니다. 기본은 매 Epoch 저장이며, TRAIN은 기본 100 Step마다 고정 Train 샘플 추론을 저장합니다. 저장 주기는 학습 설정에서 변경하며 Train 주기 0은 비활성화입니다. Train/VAL·샘플·태스크 선택과 가로 Epoch/Step 타임라인으로 실제 입력·정답·예측을 확인합니다. 데이터가 4개 미만이면 실제 개수만 표시합니다.
- **지표**: Seg mIoU/Pixel Accuracy/Dice, BEV IoU/Dice/Precision/Recall, Depth AbsRel/RMSE/MAE/δ, Detection AP/Precision/Recall 등 실제 Epoch 통계를 표시합니다. Loss와 오차는 최소, IoU/AP 등은 최대를 Best로 표시하고 해당 Epoch도 제공합니다. 정의할 수 없는 지표는 비워 둡니다. 그래프 높이는 기존의 약 1.5배이며 실행 로그는 기본으로 접혀 있습니다.
- **예상 시간**: 완료된 Epoch의 실제 평균 소요시간으로 남은 시간과 예상 완료 시각을 계산합니다. 첫 Epoch 전에는 계산 대기를 표시하고 일시정지 시간은 경과 시간에 포함하지 않습니다.
- **결과**: `결과 확인`에서 모델·옵티마이저·학습률·Batch와 저장 지표·예측 이력을 확인합니다. 동일 VAL 데이터셋의 실험끼리는 같은 샘플·태스크와 모델별 Epoch를 선택해 예측 이미지를 비교합니다.

세부 지표 정의·저장 구조·제한은 [학습 모니터링 문서](../TRAINING_MONITOR_KO.md)를 확인하세요. 실제 CARLA·CUDA 전체 학습은 이 환경에서 미검증이며 CPU·프로세스·브라우저 검사와 구분합니다.

## 웹에서 CARLA 관리

- 설치 위치는 프로젝트의 `carla/`로 고정되며, 완전한 CARLA **0.9.15** 설치가 있으면 재사용합니다. 로컬 실행은 CARLA 주소를 `localhost` 또는 loopback IP로 설정한 경우에만 가능합니다. 선택한 연구 Python의 CARLA 클라이언트도 **0.9.15**로 확인합니다. 없는 경우에만 binary wheel을 의존성 설치 없이 추가하며, 기존 다른 버전이나 손상된 클라이언트는 덮어쓰지 않고 오류를 표시합니다.
- 연구 Python의 pip가 오래되었거나 없으면 캐시한 pip 24.0 wheel 실행기를 사용합니다. 연구 환경의 pip 자체는 업그레이드하지 않습니다.
- 다운로드는 **8,386,636,048 bytes ≈ 7.81 GiB**이며 최초 **45 GiB**의 여유 공간을 검사합니다. 이미 받은 부분 파일 크기를 반영해 추가 필요 공간을 계산합니다. 주 다운로드 주소가 403 등으로 실패하면 확인된 CARLA 배포 미러로 전환합니다.
- 다운로드·압축 해제·기동 상태와 로그를 카드에서 확인합니다. 중지하면 받은 파일은 보관하며, 다시 실행하면 이어받습니다. 압축 해제는 Python 3.7에서도 경로와 링크를 검사하며 기존의 비어 있지 않은 설치 폴더를 덮어쓰지 않습니다.
- 브라우저 새로고침과 화면 이동은 설치·엔진 작업을 종료하지 않습니다. **중지**는 이 앱이 시작한 엔진에만 적용됩니다. 수집 또는 센서 미리보기 중에는 해당 작업을 먼저 중지하고 액터 정리가 끝난 뒤 엔진을 종료하세요. 단순 연결 해제는 엔진 종료와 별도입니다.

전체 8 GB 배포 다운로드와 실제 GPU 엔진 기동은 이 환경에서 검증하지 못했습니다. 설치·실행 실패 시 카드의 원인과 로그를 확인하세요.

## 센서 배치와 실제 CARLA 미리보기

**시뮬레이션 → 센서 설정**에서 활성 센서를 선택하고 위치·회전·카메라 및 LiDAR 속성을 편집합니다. 위치는 숫자로 입력하거나 상단·측면 배치도의 센서를 드래그해 변경합니다. 배치도의 점은 센서의 대략적인 위치를 나타냅니다. 정확한 설정값은 숫자 좌표로 확인하고, 실제 CARLA RGB/LiDAR 출력으로 위치와 시야를 확인합니다.

1. CARLA를 연결하고 **프리뷰 시작**을 누릅니다. 선택한 연구 Python의 별도 프로세스가 현재 맵에 미리보기 차량과 센서를 생성합니다. 연구 환경에는 `carla`, NumPy, Pillow가 필요합니다.
2. 좌표를 조정한 뒤 **프리뷰에 적용**을 눌러 선택 센서의 실제 RGB·LiDAR를 확인합니다. 프레임 시각과 적용 상태를 함께 확인하세요.
3. 적용은 현재 미리보기에만 반영합니다. 수집에도 사용할 설정은 별도로 **센서 설정 저장**을 눌러 보존합니다. 미리보기를 중지한 뒤 수집을 시작합니다.

미리보기는 최신 JPEG만 유지합니다. 요청 프리뷰 속도의 기본값은 **24 FPS**, 입력 범위는 **정수 1~60 FPS**입니다. 설정에서 FPS를 저장한 뒤 실행 중인 센서 화면에서 **프리뷰에 적용**을 누르면 기존 2 FPS를 포함한 현재 센서의 갱신값도 바뀝니다. 화면은 저장 목표·현재 센서 목표·실제 수신/출력 FPS를 구분합니다. 실제 수신·표시 속도는 CARLA 시뮬레이션 주기와 GPU·인코딩·전송 성능에 제한되므로 요청값과 다를 수 있습니다. RGB 캡처는 긴 변 최대 **640 px**로 제한하며 수집용으로 저장한 이미지 해상도는 변경하지 않습니다. LiDAR 점군 화면은 실제 센서 데이터를 사용합니다.

미리보기는 **현재 CARLA world/map**을 사용하며 맵을 불러오거나 world의 동기 설정을 변경하지 않습니다. 앱이 소유한 동기 모드 CARLA에만 tick을 보내므로, 외부 동기 모드 서버에서는 외부 실행기가 tick을 보내야 새 프레임이 생성됩니다. 중지할 때 이 미리보기가 생성한 센서와 차량만 정리합니다. 미리보기가 준비·실행·정리 중일 때는 수집·학습 시작, 엔진 종료, 연결 해제와 서버 주소·포트·연구 Python 변경을 막습니다.

실제 CARLA에서의 센서 부착·프레임 수신·정리와 GPU 실행은 이 환경에서 미검증입니다. 하드웨어 없는 테스트 통과를 실제 CARLA 동작 검증으로 해석하지 마세요.

## 학습 입력·출력 선택과 가중치 준비

학습·검증 경로와 입력 카메라를 선택하면 양쪽 분할의 **모든 장면**에서 필요한 파일과 `front_cam_rgb` 기준 frame ID를 검사합니다. 데이터가 없거나 일부만 있거나 ID가 맞지 않는 센서·태스크는 **회색으로 비활성화**하고 이유를 표시합니다. 충족하지 못한 필수 조건은 **빨간색 안내**로 표시합니다. Seg·Depth·OD는 선택한 모든 카메라의 해당 라벨이 필요합니다. BEV는 카메라 1개 이상과 선택한 학습 레이어의 실제 라벨이 필요합니다.

BEV를 끄면 BEV 디코더는 **None**이 됩니다. 이는 기존 연구 모델의 비활성 forward 분기를 사용하는 설정이며 새로운 모델 알고리즘을 추가하지 않습니다. 파일 유무 검사는 학습 가능성 전체를 보증하지 않으므로, 실행 전 준비 검사에서 보정값·이미지 크기·모델·CUDA·의존성도 확인합니다.

**준비 상태 검사**를 누르면 선택 인코더에 필요한 공통 모델 registry에 등록한 선택 인코더의 공식 가중치를 백그라운드에서 다운로드합니다. 저장 위치는 `.runtime/cache/torch/hub/checkpoints/`이며 공식 파일명에 포함된 SHA256 접두사를 검증한 캐시가 있으면 재사용합니다. 다운로드·검증 진행률과 실패 원인을 화면에서 확인할 수 있습니다. 이미 있는 파일의 검증에 실패하면 파일을 덮어쓰지 않고 원인을 안내합니다. 일반 상태 조회만으로 다운로드를 시작하지 않으며, CUDA/PyTorch 등 연구 패키지는 변경하지 않습니다.

공식 파일 두 종류의 실제 다운로드·검증과 Python 3.7에서 네트워크 없이 캐시 재사용을 확인했습니다. 가중치 검증 기록 (local-only artifact: `docs/pretrained-validation.json`; not distributed / 로컬 검증 자료·미배포)에서 범위를 확인하세요. 이후 실제 CPU에서 ResNet34·기존 EfficientNet-B0·MobileNetV3 Small의 가중치 로딩과 forward까지 추가 검사했습니다. CUDA 전체 학습은 미검증이며 QA 가중치는 프로젝트 배포물에 포함하지 않습니다.

## 무엇이 표시되는가

시뮬레이션 환경·로컬 CARLA·연결 패널은 펼치거나 접을 수 있고 선택을 저장합니다. 사용자 선택이 없으면 준비 완료나 수집 진행 시 자동으로 축소합니다. 수집 화면은 모든 맵에서 저장을 완료한 샘플/전체 목표, 백분율, 현재 맵 수와 경과 시간을 표시하며 중지해도 실제 수를 유지합니다.

진행률은 작업 이벤트에서, Loss/metric은 학습 루프의 실제 계산값 또는 저장된 CSV/로그에서 읽습니다. 데이터나 실행 기록이 없으면 빈 상태를 표시하며 예시 성능값을 채우지 않습니다.

미리보기는 두 종류입니다. **수집 화면의 카메라/BEV**는 수집기가 이미 저장한 최신 프레임을 읽으며, 저장 전에는 빈 화면을 표시합니다. **센서 설정 화면의 RGB/LiDAR**는 위 절차로 별도의 실제 CARLA 센서를 실행하며, 데이터 수집 없이 배치를 확인할 수 있습니다.

브라우저 새로고침과 화면 이동으로 작업이 끝나지 않습니다. 실행 상태와 설정은 `.runtime/studio/` 아래에 저장되고 실험별 설정 사본·이벤트·결과를 보존합니다. 수집·학습·센서 미리보기는 서로 동시에 실행할 수 없습니다.

상단 **KO / EN**에서 화면 언어를 전환합니다. 언어 선택은 브라우저 `localStorage`에 저장되며, 전환 중 입력하던 폼 초안을 보존합니다. 새로고침과 언어 전환은 서버 작업을 중지하지 않습니다. 프로젝트명·경로·사용자 데이터·원시 로그는 번역하지 않고 원문으로 표시합니다.

## 지원 범위

- 인지 모델: ResNet18/34/50/101, 기존 EfficientNet 및 torchvision B0/B1, MobileNetV3 Small/Large, ConvNeXt Tiny. 이미지 FPN/Bi-FPN/UNet, BEV ResNet/EfficientNet/UNet. [지원 조건·확장 방법](../MODELS_KO.md).
- CARLA: 웹 설치·기동·중지, 센서 배치 편집과 실제 RGB/LiDAR 미리보기, 기존 수집 코드의 타운·센서·주행/BEV 생성, 외부 서버 연결.
- 결과 분석: 저장 학습·검증 metric 비교. 원본에는 독립 주행 평가기가 없었습니다. 이번 Roach 통합에는 `scripts/validate_roach_carla.py`를 추가했으며, 실제 서버 비교 결과는 아직 없습니다.
- 원본 Django에 이름만 있던 PPO/SAC/DQN·YOLO·BEVFormer 학습과 W&B 모의 연결은 새 앱에서 제공하지 않습니다.
- 원본 모델의 모든 태스크 조합을 GPU에서 검증하지 않았습니다. 먼저 소량 수집과 짧은 학습으로 확인하세요.

## 문제 해결

| 증상 | 확인할 내용 |
|---|---|
| CARLA 설치 실패 | CARLA 카드의 여유 공간·다운로드 상태·로그 확인. 받은 파일은 다시 실행할 때 이어받음 |
| CARLA 클라이언트 준비 실패 | 선택한 연구 Python의 설치 권한·지원 wheel과 로그 확인. 기존 다른 버전·손상된 carla는 자동 교체하지 않음 |
| CARLA 기동/연결 실패 | 연구 Python과 서버의 0.9.15 버전 일치, GPU/Vulkan, RPC 포트와 다음 두 포트의 사용 여부, 엔진 로그 확인 |
| 센서 미리보기 프레임이 없음 | 현재 맵의 차량 생성 가능 위치, 연구 Python의 carla·NumPy·Pillow, 미리보기 로그 확인. 외부 동기 모드 서버에는 별도 ticker 필요 |
| 좌표 수정이 실제 화면에 반영되지 않음 | 미리보기에 적용을 눌렀는지, 적용 상태와 프레임 시각이 갱신됐는지 확인. 수집에 사용할 값은 센서 설정도 별도 저장 |
| CUDA 또는 모듈 없음 | 웹 가상환경 대신 기존 연구 환경 Python을 설정했는지 확인 |
| 학습 데이터 없음/형식 불일치 | 장면 분할, front_cam, 선택 태스크별 라벨과 프레임 정합성 확인 |
| 학습 센서·태스크가 회색 | 선택한 학습·검증 경로의 모든 장면에 해당 센서·선택 카메라의 라벨과 일치하는 frame ID가 있는지 확인 |
| 사전학습 가중치 없음/준비 실패 | 준비 상태 검사로 공식 파일 다운로드를 시작하고 원인·진행 상태 확인. 네트워크 또는 캐시 검증 실패 시 원인을 해결한 뒤 재시도 |
| 경로 저장 거부 | 프로젝트 내부 상대 경로 또는 내부 절대 경로인지 확인 |
| 작업 실패 | 작업 패널의 원인 메시지와 로그 확인. 실패 상태를 성공으로 표시하지 않음 |
| 기존 데스크톱 실행 필요 | `start-desktop.sh`; 기존 Pygame·systemd 환경 및 의존성 필요 |

## 선택적 외부 접속

기본은 로컬 전용입니다. 외부 바인딩을 명시적으로 선택하려면 24자 이상의 `SDV_AUTH_TOKEN` 환경변수를 설정하고 `./start.sh --host 0.0.0.0`으로 실행합니다. 브라우저에 접속 키 입력창이 나타나며 키는 해당 탭의 세션에 저장됩니다. 외부 호스트에서는 인증된 상태 조회 polling을 사용합니다. 직접 인터넷 공개보다는 신뢰하는 네트워크 또는 TLS reverse proxy/SSH 터널로 접속하세요. 별도 사용자 계정·역할 관리·TLS 종료는 포함하지 않습니다.

## CPU 검증 다시 실행

```bash
.venv-web/bin/python -m pip install -r requirements-dev.txt
.venv-web/bin/python -m pytest -q tests
.venv-web/bin/python scripts/check_web.py
```

실행 시 `.venv-web-py37` 등 다른 웹 가상환경이 표시되었다면 위 명령에도 해당 폴더를 사용하세요.

위 테스트는 격리된 임시 파일과 소형 프로세스를 사용합니다. 학습 fixture 지표는 파서/화면 검증용이며 실제 연구 성능이 아닙니다. CARLA 또는 GPU를 자동으로 시작하지 않습니다.
